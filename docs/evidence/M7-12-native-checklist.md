# M7-12 native checklist

Run each row on the exact PR head. Record the source SHA, OS/WebView versions, result, and evidence. Do not use `?fixture=1` or mock data. If a real agent or approval cannot be arranged, mark the relevant result UNPROVEN rather than substituting fixtures.

## macOS — WKWebView

1. **macOS — WKWebView: live data, event refresh, responsive layout and keyboard access.**
   - Setup: Use a registered project and a real daemon with two real agent-backed tasks in `Running`, one pending approval, and an installed/configured agent that can admit another task. Do not use fixture mode or mock data. Create an evidence directory with `EVIDENCE="$(mktemp -d "${TMPDIR:-/tmp}/M7-12-macos-XXXXXX")"`; record `git rev-parse HEAD`, `sw_vers`, and the WebKit version in `$EVIDENCE/environment.txt`.
   - Steps: From `apps/desktop`, run `npm ci`, then `npm run tauri dev`; use the native app window. Verify both running tasks and the pending approval appear. Confirm the panel badge equals the Attention list and both the Review navigation and top-bar counts. Submit another real task / cause another approval event without reloading; confirm the queue, attention row, and all three counts update. Use Web Inspector to resize the WebView to exactly 961 CSS px and 960 CSS px (`window.innerWidth`); confirm right docking at 961 and the existing stacked row below the top bar and before main at 960. At both widths, use Tab/Shift+Tab and Enter/Space to focus and toggle Workspace activity, Execution queue and each queue subgroup, Attention, and Agent slots; verify visible focus. Verify live Agent slots and budget do not show fixture values (`20 / 24`, `20 of 24`, `$26`).
   - Expected: Values match the real daemon, event changes appear without reload, layout switches at 961/960 CSS px, and every disclosure is keyboard-operable.
   - Evidence: `$EVIDENCE/M7-12-macos-live-activity.png`, `$EVIDENCE/M7-12-macos-event-refresh.png`, `$EVIDENCE/M7-12-macos-961px.png`, `$EVIDENCE/M7-12-macos-960px.png`, `$EVIDENCE/M7-12-macos-results.txt` (task/approval IDs, viewport width, devicePixelRatio, and PASS/FAIL per check).

In PowerShell, create `$Evidence = Join-Path $env:TEMP ("M7-12-windows-" + [guid]::NewGuid().ToString("N"))`, then `New-Item -ItemType Directory -Path $Evidence`; record `git rev-parse HEAD`, the Windows version, and WebView2 Runtime version in `$Evidence\environment.txt`.
   - Steps: From `apps\desktop`, run `npm.cmd ci`, then `npm.cmd run tauri dev`; use the native app window. Verify both running tasks and the pending approval appear. Confirm the panel badge equals the Attention list and both the Review navigation and top-bar counts. Submit another real task / cause another approval event without reloading; confirm the queue, attention row, and all three counts update. Repeat at the normal and 200% Windows display-scaling settings, recording `window.innerWidth` and `window.devicePixelRatio`. At both widths, use Tab/Shift+Tab and Enter/Space to focus and toggle Workspace activity, Execution queue and each queue subgroup, Attention, and Agent slots; verify visible focus. Verify live Agent slots and budget do not show fixture values (`20 / 24`, `20 of 24`, `$26`).
   - Expected: Values match the real daemon, event changes appear without reload, the layout switches at 961/960 CSS px under both scaling settings, and every disclosure is keyboard-operable.
   - Evidence: `$Evidence\M7-12-windows-live-activity.png`, `$Evidence\M7-12-windows-event-refresh.png`, `$Evidence\M7-12-windows-961px.png`, `$Evidence\M7-12-windows-960px.png`, `$Evidence\M7-12-windows-results.txt` (task/approval IDs, viewport width, devicePixelRatio, scaling setting, and PASS/FAIL per check).
