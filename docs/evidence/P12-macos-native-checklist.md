# P12 native macOS acceptance checklist (WKWebView)

This checklist is for the integrated Tauri app on macOS. Do not substitute Chrome, jsdom, screenshots from a browser, or an earlier source candidate for native acceptance. The final run is pinned only after the orchestrator sends `GO <sha>`; record that full SHA in every run record. Run in the task worktree with a fresh, unique Cargo target directory, app data directory, and evidence directory. Preserve every failed attempt in its own directory. Do not modify product code or `board.json`.

## Run setup and evidence rules

1. In the task worktree, record `git rev-parse HEAD`, `sw_vers`, `node --version`, `npm --version`, `rustc --version`, and the webview user agent from the WKWebView inspector. Record the configured geometry from `apps/desktop/src-tauri/tauri.conf.json`: initial 1280×800 and minimum 760×600.
2. Use `AGENT_ORCH_DATA_DIR=/private/tmp/<unique-run>/app-data` and the real debug daemon at `$CARGO_TARGET_DIR/debug/orchestrator-daemon`. To make S1–S6 reproducible without touching user data, create an isolated repository under `<unique-run>/repo`, initialize it with a `main` commit, and run `$CARGO_TARGET_DIR/debug/examples/seed_review <app-data> <repo> <worktrees> p12-review-task` before starting the daemon. This creates project `e2e-project` and one reviewable real task. Set `AGENT_ORCH_TRACE_REQUESTS=1` before app launch; the daemon log then records method names/request IDs/outcomes without parameters or results. Never use or seed the user's normal `~/.local/share/agent-orch` data. Keep logs and screenshots in the unique run directory while testing; copy only artifacts under 1 MB into `docs/evidence/p12-macos-<sha7>/`. For larger video, leave it under `/private/tmp/p12-macos-<sha7>/` and record its SHA-256 and path.
3. Launch with `AGENT_ORCH_DATA_DIR=<unique data dir> AGENT_ORCH_DAEMON_BIN=<real daemon> AGENT_ORCH_TRACE_REQUESTS=1 CARGO_TARGET_DIR=<unique target> npm run tauri dev` from `apps/desktop`. Confirm the window is the `Agent Orchestrator` Tauri app running in WKWebView. Record app PID, window position/size, display scale, connection state, and exact route hash.
4. Use AppleScript/System Events for window resizing and keyboard input. Capture the app window with `screencapture -l <windowid>` (or its measured screen rectangle with `screencapture -R`). For first-paint checks, start `screencapture -v -V 8` before launching the app and preserve the video. Attach WKWebView's Develop/Web Inspector when available. In its Console, save results of the read-only DOM measurements below; do not edit app files to add an inspection hook.
5. Horizontal overflow measurement (table-specific inner scrollers are allowed):
   ```js
   [...document.querySelectorAll('.shell,.shell-strip,.shell-body,.shell-sidebar,.shell-content,.shell-topbar,#shell-main,.shell-activity,.shell-resources')].map(e => ({slot:e.getAttribute('aria-label') || e.id || e.className, clientWidth:e.clientWidth, scrollWidth:e.scrollWidth, overflows:e.scrollWidth > e.clientWidth + 1}))
   ```
   Popover bounds measurement: for each visible popup/dialog/listbox, compare its `getBoundingClientRect()` with `document.documentElement.clientWidth/clientHeight`; no edge may extend beyond the WKWebView content viewport.
6. Record a PASS, FAIL, or UNVERIFIED for every checklist ID. A missing project/task or unavailable native inspector is UNVERIFIED for the affected criterion; do not substitute fixture-browser output. For a failure, preserve a minimal reproduction, screenshot/video, exact route, and likely source `file:line` in the report.
