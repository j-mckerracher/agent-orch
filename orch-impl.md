# Orchestration learnings (durable)

Recorded by the coordinator on 2026-11-08 (America/Denver, -07:00). Add only learnings that change how future orchestration or implementation is done. Routine status belongs in board.json and the execution plan.

## Worker runtime

- The OMP provider ID for gpt-6-luna is `openai-codex`. The `codex/gpt-6-luna` form in orch-impl-m.md is not resolved by OMP ("Model not found"). Verify the real model, provider, and thinking level with RPC `get_state` (`model.provider`, `model.id`, `thinkingLevel`) before sending a prompt.
- `utilities/omp_headless.py` embeds a reference to `orch-impl-w.md`. When the user selects the Mac primer, tell workers to read `orch-impl-m.md` explicitly; the launcher's stale reference must not switch their required model or thinking level.
- On 2026-11-08, `omp plugin doctor --json` reported that the installed `ponytail@1.0.57` has no OMP/Pi manifest and is not an OMP plugin. The separately discovered Ponytail skill does not prove that extension hooks are active. Verify the actual extension and its session load notification before permitting worker code edits.
- In the Copilot app sub-agent runtime, the parent session's `events.jsonl` records the actual model and `reasoningEffort` in `subagent.configured` for the exact `agentId`; the agent listing omits the effort. Neither that event nor an installed plugin proves Ponytail hooks are active. If hooks are unavailable, follow the primer's fallback only when the installed Ponytail `AGENTS.md` and required task guidance can be read, and record the limitation.
- When a worker contract specifies a model and reasoning level, set both explicitly on every task launch. A default model selection does not establish compliance; preserve and independently rerun an unconfigured attempt.
- The RPC driver must pass absolute paths for `--session-dir` and `--resume`. OMP runs with its working directory set to the worktree, so a relative path fails with "Session not found" and exit 4. A resumed session keeps its original sessions directory, so resume from the first run's `sessions/` folder.
- Give each OMP bootstrap the absolute primer path in its task worktree and verify a successful `read`. A relative filename led a reviewer to search for the primer and stop without reading it; resume the same preserved session after correcting the prompt.
- An OMP worker's `proc://` surface can omit coordinator RPC `get_state` even when the coordinator independently verifies that session. Preserve the blocked attempt and worktree, then resume the same session with the coordinator's exact provider/model/thinking and required-read verification, explicitly stating that this satisfies the gate. Confirm bootstrap reads and assignment restart; a prior blocked report is not task completion.
- After a deadline, an OMP resume can continue a queued turn immediately after bootstrap reads, before a new assignment is sent. Preserve the old attempt, steer new evidence to a separate directory, and avoid sending the same work twice.
- Interactive requests are the only extension UI frames that need a reply (select, confirm, input, editor). Presentation frames such as the caveman `setStatus` spinner arrive several times a second and grew event logs to hundreds of megabytes. Log only the interactive methods.
- A worker can stall inside one very large generation: no bytes and no events for more than 20 minutes. Sample `events.log` byte growth over 60 seconds to tell a stall from progress. An aborted assistant message can arrive without a terminal agent event, so verify process exit; after a bounded grace period, stop the owned driver, preserve its worktree and session, and resume with smaller writes.
- Driver and validation launch: a job started with `nohup` or `&` from a non-interactive shell inherits ignored SIGINT. This also invalidates interruption tests: three conformance tests hung until an attached rerun passed unchanged source. Use tool-native attached sync/async sessions, not shell backgrounding. Stop only owned processes and confirm exit. Use absolute paths; in `cd X && cmd &` the `cd` runs in a subshell and the next command starts in the wrong directory.
- Always pass `--deadline-minutes` explicitly and record it in the board. The driver's default is 240 minutes, which is not a box. A stalled run with a 180-minute deadline kept writing uncommitted code for over an hour.
- Monitor deadlines on queued follow-ups as well as running workers. A review queue expired while waiting for integration; preserve its attempt, confirm no reviewer started, and create a fresh queue before the prerequisite completes.
- A `reported` worker phase means a report exists, not that its verdict passed. Gate integration and publication on the coordinator-verified scoped verdict, exact candidate, and report digest; block unresolved findings before creating the downstream worktree or pushing.
- A resumed OMP reviewer can save its report under the previous assignment's artifact directory despite a new requested path. Follow the recorded write and final report path, preserve the original, and bind that exact report to the gate instead of assuming the expected file exists.
- A worker that spends 30 minutes or more on reads with no writes needs intervention. The M5-02 worker made about 250 read calls before its first write. Stop it, keep the session, and resume with a write-first instruction.

- Verification briefs must not halt on the first environment-class failure. The M5-01 verifier stopped at a Windows C cross-build failure and skipped the code review. Tell verifiers to classify an environment failure, record it, and continue with every independent step.
- Windows cross-checks on macOS cannot compile crates that link C code. The daemon depends on libsqlite3-sys, and `cargo check --target x86_64-pc-windows-msvc` fails on macOS for lack of Windows C headers. Verify that crate on the Windows machine. The ipc crate's cross-check is valid on macOS.
- Cross-platform modules gated with `cfg(unix)` hide the Windows implementation. In crates/orchestrator-ipc/src/lib.rs, the transport, session, server, auth, and client modules are `cfg(unix)`. Adding a Windows transport requires changing those gates to `any(unix, windows)`, so plan that scope up front.

## Briefs and scope

- Three workers were blocked by briefs that asked for a write outside their writable scope: an evidence directory, a runtime manifest, and a stale-lock store change. Every path a brief asks a worker to write must be listed in its writable scope. Amend the scope and resume the same session rather than letting the worker stop.
- Copy each item's `details` from board.json verbatim into its brief. One brief was written from plan text, not from the board, and omitted required scope (the data-directory lock and process identity). Check each brief against the board before dispatch.
- A board item can name an authoritative read-only source outside a worker's worktree. Permit that exact file only when the source is authorized and no higher-priority restriction applies. Record its full path and hash. Otherwise an isolation rule can prevent verification.

## Cross-machine handoffs

- For Windows work on this project, the user directs runbooks to `j-mckerracher/agent-orch`. Publish each approved runbook on a dedicated non-protected branch. Pin the exact source commit. Make the commit reachable from the runbook branch. Publish returned evidence on a separate ref.
- Remote workers cannot read the coordinator's local session folder without an established transfer path. Send the exact branch and runbook URL over a verified channel. Publication alone does not prove that the worker received the runbook or started work. Keep local-only diagnostics local. Verify evidence before counting results.
- Before publication, verify the effective GitHub identity and repository push permission for the chosen transport. SSH key selection and an inherited `GH_TOKEN` can differ from the active CLI keyring account. Use only a user-authorized account with per-invocation authentication; do not switch shared global accounts, expose credentials, or change the destination to bypass a denial.
- Redact structured evidence values before JSON serialization. JSON doubles Windows backslashes, so replacing raw paths afterward can miss them. Test escaped, UNC, short-path and scp-style remote forms, then scan every publishable file and refuse publication on a sensitive match. Do not replace usernames or hostnames as unrestricted substrings: names such as `main` can corrupt Git evidence.
- A Rust target check that substitutes a no-op C compiler and empty native archives is not cross-build or native acceptance evidence. Label that limitation explicitly. Compiler-expanded Windows test descriptors can derive expected counts, but validate the method against a measured baseline and require the exact candidate's native listing and results.
- Bounded child execution does not bound evidence redaction. Test URL/scp regexes on multi-megabyte word runs: unanchored patterns rescanned quadratically. When anchoring for linear time, preserve redaction of digit/punctuation-prefixed URL hosts, paths and queries; a fail-closed publication scanner does not justify a redaction regression.
- Name ref-snapshot captures by the full namespace, not only the basename: `orch/<name>` and `docs/<name>` collide otherwise and overwrite provenance. Capture both refs in one producer invocation or use namespace-qualified filenames; preserve any lost-capture disclosure and record a fresh independent snapshot.
- Check free space in bytes on the actual build and temporary-file volumes before a native run. PowerShell's `Temp` drive can be an alias of `C:`, not additional storage; distinguish GB from GiB, record the command exit, and stop before partial gates if the stricter threshold is not met. `Get-PSDrive` lists session drives, not all Windows volumes; map paths to actual volume identities or limit conclusions to the observed drives.
- A PowerShell transcript can keep recording after a diagnostic and capture unrelated private output. Avoid it or guarantee it stops on success, error, and blocked exits. Treat missing drive metrics as unavailable, not zero or a successful measurement.
- Diagnostic and preflight evidence refs can share an acceptance-run prefix. Exclude known diagnostic refs from acceptance polling, and inspect the exact tested commit, commands, and producer exits before treating any ref as acceptance evidence.
- A successful `git ls-remote` exit can mean no ref matched. Require the exact expected ref and SHA in its output when verifying publication; use `--exit-code` only as an additional no-match signal.
- `gh api` changes its default method from GET to POST when `-f` or `-F` fields are supplied. Use `--method GET` for read-only queries with fields; otherwise a 404 can describe an unintended POST, not missing read access or resources.

## Integration and board edits

- When acceptance requires an unchanged test suite, compare original test blobs, including deleted files, and run those originals against the exact integrated candidate. A passing modified suite or higher test count is not proof; resolve conflicting requirements with the user rather than removing assertions or adding inert test-only code.
- When two migrations are written in parallel they can claim the same number (M7-07 and M7-08 both used `0030`). The integrator must renumber and run a store-open test, because a duplicate breaks opening the store.
- Parallel adapters that each add a capability to the handshake conflict in shared wiring files and implement optional-capability fallback separately. Specify one optional-capability mechanism (retry the handshake once without it; the panel shows `unsupported`) before dispatching adapter work.
- Independently refreshed UI data can retain stale rows while counts or search indexes update. Preserve each source's observation and error state; a newly built aggregate is not proof its inputs are fresh. Test mismatched snapshots and retained data after refresh failure.
- A non-null adapter project ID may itself come from stale `tasks.list` data, not an independent authority. Preserve its provenance, invalidate task-derived routing on events, and check current project membership; test non-null IDs as well as null fallbacks.
- A tagged fallback can be type-safe and read-only yet still be mislabeled or duplicated in search and navigation. Audit every consumer's labels, routes, actions, and deduplication, and include shared contract tests when adding a source variant.
- A UI case-insensitive filesystem collision (`inventory.ts` vs `Inventory.tsx`) breaks macOS checkouts; name model files distinctly.
- Shell tool calls do not retain a previous call's `cd`. Use `git -C` with the absolute task-owned worktree path for every mutating Git command, and verify the path and HEAD first. Run Cargo with an absolute `--manifest-path` or a `cd` in the same call, and keep build output in a task-owned target directory. For npm installs, tests, and builds, verify the actual working directory and runner root as well as HEAD: a successful run from another checkout does not verify the candidate. Preserve mistakes for inspection; do not repair a shared checkout with an unapproved reset or cleanup.
- `npm ci` can exit zero while reporting `EBADENGINE` for dependencies. Record Node and npm versions and inspect install warnings and dependency engine requirements before treating a native test run as supported; an install pass alone does not establish runtime compatibility.
- The desktop `vitest.e2e.config.ts` runs in Node mode and does not provide Playwright/Cypress, but installed headless Chrome can run real DOM, computed-style, and geometry checks without adding a browser dependency. Assert the observed `window.innerWidth`: Chrome reported 500 CSS px when 390 px was requested, so the launch argument alone does not prove the viewport.
- OMP may automatically try an unavailable `memory://root/memory_summary.md` before bootstrap. Scope "stop if a read fails" to the required primer and skills; otherwise a worker can stop before reading them. Preserve the failed session, resume it, and verify the required reads and runtime again.
- Reuse an exclusive Cargo target cache across revisions in one checkout. When switching worktrees, invalidate changed local packages with Cargo's package-scoped clean before measured runs. Cargo freshness reused a newer CLI binary for an older checkout and produced a false GREEN. Source touches and `Compiling` lines are not sufficient provenance. Retain unchanged external dependencies. Keep evidence directories unique per attempt. Check disk capacity before broad builds and recheck a low-space alert before cleanup, because availability can recover. Reclaim only verified superseded task-owned caches, never source worktrees or raw evidence.
- A resumed worker can use a worktree whose original status says `reported` while its new status has a different name. Before cleanup, map all current and queued workers to their actual worktrees using session paths and runtime context, then recheck immediately; old status and no open files do not prove a cache is idle.
- Parallel `edit` calls on board.json in one response can race. After a batch of edits, reparse the file and check every required key and dependency reference. One edit once dropped an item's `id`, `milestone`, and `title`. Board task schemas vary: early milestones may omit `acceptance` and `verification`, so validate common keys globally and item-specific keys where applicable. Make validation failure stop the commit command; a separate unchecked shell command can commit despite a failed check.
- Validate priority depth before dispatch: each task's priority must be one more than its deepest dependency, and the graph must be acyclic. A newly added task once shared its prerequisite's priority, making same-priority concurrent execution unsafe.
- QA scripts, counters, synthetic negative-test logs, and parser results that support a verdict remain evidence after approval. Keep them outside retiring worktrees. If evidence is lost, disclose the loss and label affected historical results `FROM_REVIEW`; new runs are new evidence, not restored originals.
- Candidate and evidence checkouts can contain stale `board.json` snapshots. Only the coordinator's current board is the scheduling record; give workers the current item, status, and dependencies in their briefs, and have them report conflicting historical snapshots rather than schedule from them.
- Candidates that each add dependencies conflict in Cargo.lock. Resolve by keeping one side, running an unlocked `cargo metadata` to add the new entries (existing pins are preserved), confirming the lock diff only adds lines, then verifying with `cargo build --locked`.
- Tell every worker not to amend or rewrite commits. If a worker nevertheless replaces an unpublished commit, preserve the original SHA under a separate ref and review and test the new exact head; earlier evidence does not automatically transfer.
- Before pinning a Windows runbook, verify that the candidate contains each relevant Windows fix. Ancestry is sufficient when the fix commit is present, but its absence is not proof the fix is missing: independently compare the exact source when a change was integrated by another route. One integration branch lost the stable file-identity fix (`cbbad05`), while a later candidate contained equivalent `GetFileInformationByHandle` code without that ancestry. macOS tests cannot catch unstable Windows API regressions; also run `cargo check --target x86_64-pc-windows-gnu --tests` on each crate that builds on macOS.
- Verify each candidate independently before merging: scope against the brief, `cargo test --locked --workspace`, and clippy for the touched crates, judged by each command's own exit code. Persist per-attempt commands, producer exits, stdout/stderr and source HEAD/status before and after outside the measured checkout. A later clean commit and a chat summary cannot reconstruct unsaved failed runs or establish which bytes an earlier test exercised.
- Git worktree creation can print progress before its fatal error. Preserve the causal error chain and useful stderr when reporting failure; taking only the first line hid the native failure. Do not classify retries from an unrestricted `already exists` substring: that phrase in an unrelated failing path caused 1024 retries and obscured the real error.
- Git for Windows can reject a Rust-canonicalized verbatim path as a worktree destination (`//?/C:/...`, `Invalid argument`). Keep containment checks on the original path, and convert only safely equivalent drive/UNC forms at the Git boundary; preserve long-path and verbatim-only semantics. Require a native real-Git regression with a canonicalized root: plain `TempDir` roots did not reproduce the CLI failure.
- Path-equality fixtures (e.g. delivery `destination` vs `Repository::path()`) must produce the path through the same API production uses. On Windows `fs::canonicalize` yields `\\?\C:\…` while `git rev-parse --show-toplevel` yields `C:/…`; Mac cannot expose the mismatch, so such tests are only proven by native Windows runs.

## Safety-critical behavior

- Crash recovery needs a stale-lock takeover. A lock from a dead holder must be reclaimed by renaming it to a private directory, verifying the inode and token, and only then removing it, restoring it if verification fails. Never remove a lock by name alone.
- An adapter must never report a completed turn as success when the process then exits non-zero. The conformance suite found this in Codex, Claude Code, and Pi, and it must stay tested. A malformed protocol line on an exit-0 run is a protocol violation, not success.
- Process identity (PID, process group, start time) must be checked before any signal is sent. A PID alone is not proof of ownership.
- A start-time mismatch on a live PID does not prove PID reuse. Linux start time is `btime` plus ticks, and `btime` shifts when the wall clock steps. Release or retire a session only when its recorded process group is provably dead. A review caught a fail-open where a live lead with a drifted start time was released.
- For an exited-owner test fixture, start an owned process group when the observer checks group lifetime, capture the child's identity before killing and reaping it, and assert the observer actually returns `Exited`. A child sharing the test's live group or a forged start time exercises uncertainty, not genuine death. Workspace/delivery refusal tests must prove their own evidence caused refusal, rather than passing at an earlier process guard.
- A dead CLI cancellation owner does not prove its agent tree is dead. The supervisor starts the agent in a separate process group, so killing the CLI can leave that group alive. Before removing even a clean, landed worktree, check the recorded session identity and group with the same conservative recovery rule; owner-only liveness checks miss this case.
- Reconciled delivery `Confirmed` proves that a recorded review ref points to the exact candidate, not that it was integrated. The planned verification/Succeeded transition precedes delivery; contradictory task state needs inspection, not inferred success. Task classification is advisory and never authorizes cleanup or bypasses delivery approval.
- Scheduling-gate policy distinguishes settled terminal records from records interrupted in the current pass. Inspect workspace and delivery evidence before failure transitions; an automatic `Failed` write must not hide unresolved ownership or delivery. Preserve known-owned crash edits without globally blocking unrelated new tasks, but surface the actual advisory classification. Pending or ambiguous delivery journals still require read-only inspection even when the CLI has no delivery command. Inspect journals before any live-owner early return: verified live owners are exempt from process and workspace blockers, not unresolved delivery.
- When several processes write one SQLite store, a deferred transaction that reads and then writes fails at once with `SQLITE_BUSY_SNAPSHOT`, and the busy timeout does not apply. Start every writing transaction with `BEGIN IMMEDIATE`. Keep read-only transactions deferred so lock-free reads do not queue behind writers.
- The daemon holds the exclusive data-directory lock for its lifetime. Any CLI path that must commit while the daemon runs, such as a run owner confirming a cancellation, cannot depend on reacquiring that lock. Fence it with single store transactions keyed to the owner generation instead.
- Windows differences can break tests:
  - Creating a lock at an existing directory can return `PermissionDenied` on Windows instead of `AlreadyExists`. Test the reject-and-preserve contract before platform-specific error variants; do not remap a real I/O cause merely to satisfy a Unix-shaped assertion. Capture passing-test stderr with `-- --nocapture` when native acceptance requires the actual error and retention state.
  - Windows byte-range locks (`LockFile`) are mandatory. A lock that covers a file's data makes every other handle fail with OS error 33 when it reads that data. Lock a byte past EOF, for example at offset 4 GiB, so the lock record stays readable.
  - On Windows, `Child::kill` calls `TerminateProcess(handle, 1)`. A killed process therefore reports exit code `Some(1)`. On Unix it reports `None`.
  - A function body wrapped entirely in `#[cfg(unix)]` compiles on Windows as a silent no-op, and a Windows cross-check does not catch it. For example, `orchestrator-ipc` token removal did nothing on Windows and failed a native test. Before a Windows run, audit cleanup and security paths for Unix-only bodies.
  - Windows process creation time uses 100 ns units; `start_time_micros` must equal creation time divided by 10. A forged identity must preserve that relationship. Adding 1 only to creation time crosses a microsecond boundary for one of ten remainders, making the fixture invalid and returning `Unknown` instead of testing a genuine identity mismatch. Cover every remainder deterministically.
  - Named pipes here are `PIPE_NOWAIT`. std `File::read` maps `ERROR_NO_DATA` (232) to `Ok(0)`, which looks like EOF and truncates frames. Call `ReadFile` directly and treat 232 as `WouldBlock`, retried until the stream timeout.
  - Git for Windows sets `core.autocrlf=true` in its system config. A test fixture that ignores system git config but creates worktrees through code that honours it gets CRLF checkouts, so `git add -A` stages extra modified files. Set `core.autocrlf=false` in the fixture, stage files by name, and assert the committed count. Reproduce on a Mac with a system-level gitconfig and `GIT_CONFIG_GLOBAL` disabled, since a global `autocrlf=input` masks it.
  - Windows is slower to connect and spawn than a Mac. Tests with tight stream timeouts (50 ms) drop idle connections before their first call. Use seconds-scale timeouts, assert strictly so an I/O error cannot pass as an expected rejection, and reproduce on a Mac by injecting a delay after connect.
  - A test-only helper used only by `cfg(unix)` tests is dead code on Windows. Gate it with the same `cfg`.
  - Windows worktree paths are limited to about 215 characters (`'$GIT_DIR' too big`); `core.longpaths` does not help. Use a short real root such as `C:\t`. A SUBST, mapped, junction or UNC root also produces `TS2883` duplicate-path errors in TypeScript, so the harness preflight must refuse them (exit 3).
  - Node's sync `rmSync` ignores `maxRetries` for `EBUSY`; use an awaited async retry loop. In PowerShell, parse verdicts with `-cmatch` on the last `P12-WINDOWS-CHECKS:` line, because a case-insensitive `-match` counts banner lines. Do not count the operator's own monitor `pwsh` as a survivor.
  - Windows file creation inherits the folder ACL, so protect `.orchestrator.lock` and the log explicitly on creation. Use `CI=true`, not `CI=1`, for `tauri build`; `tauri build` rewrites `src-tauri/Cargo.toml`. Each tauri bridge test takes over 60 s. The daemon closes idle unsubscribed connections after 2 s and Windows worktree creation takes about 4 s, so tests must reconnect per call.
  - A harness must not require a file the bare daemon never creates, and a privacy gate must never halt publication. Any `SKIPPED` gate makes the run INCONCLUSIVE.
- Run RED reproductions in an isolated `CARGO_TARGET_DIR`. A shared target contaminates results.
- Worker and evidence commits take their author and committer from effective Git configuration, which may contain another noreply identity. Specify the exact requested identity in each brief or runbook and verify both fields; preserve existing commits rather than amending them. Inherited parent history keeps whatever email it had.
- The daemon cannot be cross-compiled for Windows from a Mac (`libsqlite3-sys` needs target C headers). Only the ipc and git crates have Windows-target checks, so the first native run of new daemon code can surface compile or test failures. Budget at least one Windows remediation round.
- Haiku 5.5 task agents given broad verification scopes looped for hours (1,000+ tool calls) and some failed on the prompt budget with no report. Give narrow scopes, require an early written report, and take the work over after 30 minutes.
- Fast-mode run (2026-11-12/13): restart the stall watchdog the moment it exits, every time. One lapse left three finished workers idle for 3 to 4 hours. Workers (Codex and Haiku) also mistyped the long session-id helper paths (`ao-push.sh`, `ao-gh.sh`) and reported BLOCKED; put helper scripts at a short stable path, or paste the paths for them to copy and tell them to `ls -l` first.
- A filtered `cargo test <name>` that matches no test exits 0 with `0 passed`, and `--test <target>` with the wrong target silently matches nothing. Check every filter against `git grep "fn <name>"` and require `1 passed` in the output (runbooks, briefs, gates).
- Computer Use cannot obtain the Tauri window (`cgWindowNotFound`, packaged .app gives `kLSNoExecutableErr`), so native WKWebView rows cannot be agent-run. Run the browser-provable rows in headless Chrome with a real daemon and label them browser-proxy; reserve the rest for a human at the Mac.
- A git worktree needs a real `npm ci` in `apps/desktop`. A symlinked `node_modules` breaks `tsc -b` (TS2883 non-portable types). Run `npm run build` or `./node_modules/.bin/tsc`, not `npx tsc` (it resolved the wrong package).
- Stacked-shell layout (≤760 px): `.shell-body` is the scroller, so the usage popover sits below the fold at rest. Popover geometry tests must `scrollIntoView` before measuring. Headless Chrome's `innerHeight` is about 87 px less than the requested `--window-size`. Adding an e2e file requires bumping `e2eFiles` and `E2E_TESTS` in `scripts/ci/expected.mjs`.
